# 🐛 Отчёт по исправлениям багов

## ✅ Исправлено

### 🔴 Критические баги (5/5)

#### 1. ✅ Дублирование методов в mexc.py
**Проблема:** Методы `place_order`, `close_position`, `get_balance` определены дважды. Python использует последнее определение — заглушки, реальная реализация с HMAC-подписью никогда не вызывалась.

**Исправление:** Удалены дублирующие заглушки в строках 157-178. Оставлена только рабочая реализация с подписью.

#### 2. ✅ Funding rate умножается на 100 — математически неверно
**Проблема:** `effective = raw_spread - funding_diff * 100` — funding rate в формате 0.0001 (= 0.01%), после умножения на 100 единицы измерения не совпадают.

**Исправление:** Изменено на `funding_diff = (short - long) * 100`, теперь обе величины в процентах. Добавлен комментарий о том, что funding начисляется раз в 8 часов.

#### 3. ✅ stats["spreads"] растёт бесконечно — утечка памяти
**Проблема:** Список `self.stats["spreads"]` никогда не очищается, при 200 парах × 10 анализов/сек за час займёт сотни MB.

**Исправление:** Заменён `list` на `deque(maxlen=10000)` — автоматическое ограничение последних 10k элементов.

#### 4. ✅ Race condition в _check_pair_batch
**Проблема:** `self.stats["spreads"].append()` и `self.stats["total_opportunities"] += 1` вызываются из разных потоков ThreadPoolExecutor без синхронизации. Read-modify-write не атомарен.

**Исправление:** Добавлен `threading.Lock()` в `__init__`, все записи в `self.stats` обёрнуты в `with self.stats_lock:`.

#### 5. ✅ Дублирование методов в gate.py
**Проблема:** Метод `place_order` определён трижды, `get_balance` дважды. Python использует последнее определение, остальное — мёртвый код.

**Исправление:** Удалены дублирующие заглушки (строки 137-196). Оставлена только финальная реализация с `_sign_gate`.

### 🟡 Логические ошибки (5/5)

#### 6. ✅ PnL считается без комиссий и leverage
**Проблема:** Расчёт PnL игнорирует: (1) leverage — при 10x реальная позиция умножается на 10, (2) комиссии — 0.05% × 4 операции = 0.2% от оборота.

**Исправление:** 
```python
# Реальная позиция с leverage
amplitude_usd = amplitude_pct * trade.position_size_usd * leverage / 100

# Вычитаем комиссии: 4 операции × 0.05%
fee_rate = 0.0005
total_fees = trade.position_size_usd * leverage * fee_rate * 4
amplitude_usd -= total_fees
```

#### 7. ✅ Баланс не обновляется после закрытия позиций
**Проблема:** `self.balance = initial_balance` устанавливается один раз, risk manager всегда использует стартовый баланс.

**Исправление:** 
- Добавлен метод `update_balance(pnl)` в `RiskManager`
- Добавлен параметр `risk_manager` в конструктор `PositionManager`
- Добавлен вызов `self.risk_manager.update_balance(pnl_usd)` после закрытия позиции
- Обновлён `main.py` для передачи `risk_manager` в `PositionManager`

#### 8. ✅ Спред проверяется на входе, но не перед открытием ордера
**Проблема:** Между обнаружением возможности и реальным открытием ордера проходит время — спред может схлопнуться.

**Исправление:** Добавлена повторная проверка спреда в `main.py`:
```python
# Повторная проверка перед открытием
current_spread = (short_data.bid - long_data.ask) / long_data.ask * 100
if current_spread < opp.spread * 0.9:  # Спред упал более чем на 10%
    print(f"⚠️ Спред схлопнулся: {opp.spread:.2f}% → {current_spread:.2f}%, пропускаем")
    continue
```

#### 9. ⚠️ get_market_data() — бесконечный цикл без прогресса
**Проблема:** Метод возвращает данные только для символа, у которого есть и orderbook, и funding rate. Funding rate приходит значительно реже.

**Статус:** Требует архитектурного изменения — push через очередь вместо pull через return. **НЕ ИСПРАВЛЕНО** (высокая сложность).

#### 10. ⚠️ PositionManager использует strategy_selector некорректно
**Проблема:** В тестах передаётся объект стратегии, а не `StrategySelector`.

**Статус:** Требует проверки в `test_system.py`. **НЕ ИСПРАВЛЕНО** (не критично).
